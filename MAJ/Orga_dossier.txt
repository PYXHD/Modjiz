/////////////////////////////////
src/app/ (Next App Router)

But : routing + pages + layouts Next
layout.tsx (root) : html/body, fonts, theme init, globals, metadata globale
page.tsx : landing (/)

app/ (sous-dossier) : routes de l’app (/app), layout “shell” (header/nav)

✅ À mettre ici :

pages, layouts, loaders, error boundaries
éventuellement app/api/* en V2 si tu fais API routes
server actions (V2) si tu utilises ça

❌ À éviter :

logique métier (calcul streak, trophies, etc.)
accès direct localStorage/DB (ça va dans data/)

/////////////////////////////////
src/components/

But : UI web (React components)
Buttons, Cards, Inputs, Modals, Header, Nav…
composants client (avec state, handlers)
composants “dumb” (purs) + “smart” (connectés aux data)

✅ Ici :

ThemeToggle, EmotionCard, TrophyItem, etc.
tests unitaires colocalisés (Component.test.tsx)

❌ Pas ici :

règles métier (ça va dans domain/)
appels DB directs (ça va dans data/)

/////////////////////////////////
src/assets/

But : fichiers bruts statiques

fonts/ : ttf/woff/woff2

img/ : images

✅ Ici :

ressources uniquement (pas de code)

structure possible : img/landing, img/icons, etc.

/////////////////////////////////
src/domain/

But : métier pur (framework-agnostic)
C’est LE dossier le plus important pour V3 (React Native).

✅ Ici :

types métier : Mood, MoodEntry, Trophy
règles : “1 entrée par jour”
calculs : streak, stats, trophées unlock
validation : format, contraintes

❌ Interdit ici :

imports Next/React
DOM, localStorage, fetch, axios

/////////////////////////////////
src/data/

But : accès données via une interface stable
Tu mets une “couche repository”.

✅ Ici :

interfaces : MoodRepository

impl V1 : localStorage
impl V2 : API/DB (ou server actions)

Objectif : ton UI appelle repo.saveEntry() et ne sait pas si ça va en localStorage ou DB.

/////////////////////////////////
src/lib/

But : utilitaires purs (helpers)
✅ Ici :

format date
helpers de string
petits calculs génériques non-métier

Différence avec domain/ :

lib = général
domain = spécifique à Modjiz

/////////////////////////////////
src/types/

But : types transverses
✅ Ici :

types partagés non métier (ex: ApiResult<T>, Nullable<T>)
éventuellement types de DTO (si tu veux)

Honnêtement tu peux aussi tout mettre dans domain/ au début, et n’avoir types/ que si ça grossit.
